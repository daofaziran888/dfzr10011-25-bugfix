# 分布式采集调度引擎

面向大规模数据采集团队的分布式采集调度引擎。覆盖采集节点集群管理、任务分片调度、结果聚合归并、节点健康监控、采集流量均衡、断点续采恢复与全局采集看板的完整分布式采集链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 业务模块

| 模块 | 目录 | 业务对象 | 主要字段 |
| --- | --- | --- | --- |
| 采集节点集群 | `cluster` | 集群节点 | 节点编号、节点地址、节点角色 |
| 任务分片调度 | `shard` | 分片任务 | 分片编号、采集计划、分片范围 |

| 采集频率控制 | `ratelimit` | 频率规则 | 规则编号、目标站点、请求间隔 |

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 看板刷新与归档口径

全局采集看板（`dashboard`）在普通面板维护之外，还承接刷新批次、导出快照与归档联动：

- **团队范围与共享**：面板按「归属团队 / 共享范围」受控。本团队可见面板声明的全量字段
  与最近成功快照；跨团队只能看到「跨团队共享」面板的摘要（不含数据范围、告警配置），
  且共享面板只读，只有归属团队能改动、刷新或归档。身份通过 `team` 查询参数（GET）或
  请求体 `values.团队`（POST/PUT）传递，缺省为采集A组值班管理员。
- **刷新结果绑定完整数据范围**：刷新批次落库时复制面板当时的声明（面板名称、显示指标、
  刷新间隔、数据范围），之后面板改字段不会污染历史刷新结果；回执数据范围与批次绑定
  范围不一致会被拒绝，缺范围的刷新直接拦下。
- **并发与失败保护**：同一面板同时只允许一个「刷新中」批次（409 冲突）；失败刷新只登记
  失败原因，不生成也不覆盖导出快照，导出区继续保留旧快照。
- **归档的两种到达顺序**：归档先行时在途批次与后续回执全部登记为「已拒绝」，导出区保留
  旧快照；刷新先行后立即归档时，导出区保留新快照的版本与时间，存储模块的归档待办注明
  最后刷新批次。面板归档后不再产生任何新快照。
- **存储模块联动**：成功刷新通过 `app/services/storage.py` 生成 `storage_snapshot`
  导出快照（保留完整数据范围、版本、生成时间），面板归档同步生成
  `dashboard_archive_task` 归档待处理清单。接口见 `/api/storage/snapshots` 与
  `/api/storage/archive-tasks`。
